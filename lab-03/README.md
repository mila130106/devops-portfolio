# Лабораторна робота 3 — Власний DevOps-інструментарій

У теці `lab-03/` зібрано три інструменти автоматизації з довідкою `--help`, кодами виходу, перевіркою параметрів, журналюванням та документацією:

* `backup.sh` — скрипт резервного копіювання з ротацією архівів
* `api_monitor.py` і `config/endpoints.json` — монітор доступності API з класифікацією збоїв та сповіщеннями
* `hooks/pre-commit` і `hooks/pre-push` — локальні Git-хуки для перевірок перед комітом та відправкою

Зміни потрапляють у гілку `main` через Pull Request із власної гілки.

## 1. Скрипт резервного копіювання (`backup.sh`)

Скрипт створює стиснений архів `.tar.gz` вказаної теки-джерела з часовою міткою формату `YYYY-MM-DD-HHMMSS` (для правильного хронологічного сортування за іменем) та зберігає лише `N` найновіших архівів цього джерела (типово `5`). Сторонні файли у теці призначення не видаляються, а шляхи з пробілами підтримуються.

### Параметри запуску
* `--source <шлях>` — обов'язкова тека, яку архівуємо
* `--dest <шлях>` — обов'язкова тека, куди складаємо архіви (створюється автоматично, якщо відсутня)
* `--keep <N>` — скільки останніх копій цього джерела зберігати (необов'язковий, типово `5`)
* `--dry-run` — показує заплановані дії без створення та видалення файлів
* `--help` — виводить призначення, параметри, коди виходу та приклад запуску

### Пояснення `set -euo pipefail` своїми словами
* **`-e` (`errexit`)** — змушує скрипт негайно завершитися при першій команді з ненульовим кодом виходу. *Без нього* скрипт міг би проігнорувати помилку створення архіву чи видалення старих копій і піти далі, записавши невірний результат або неповний бекап.
* **`-u` (`nounset`)** — забороняє використовувати неоголошені змінні та одразу завершує роботу з помилкою при зверненні до них. *Без нього* одруківка в назві змінної (наприклад, `$KEP` замість `$KEEP`) перетворилася б на порожній рядок і зіпсувала шляхи чи логіку ротації.
* **`-o pipefail`** — робить так, щоб конвеєр (`cmd1 | cmd2`) повертав помилку, якщо впала будь-яка команда в ланцюжку, а не лише остання. *Без нього* помилка на початковому етапі конвеєра могла загубитися, і скрипт вважав би крок успішним.

### Приклади запуску та виводу
```bash
./lab-03/backup.sh --help
./lab-03/backup.sh --source "/tmp/my project" --dest "/tmp/backups" --keep 3
./lab-03/backup.sh --source "/tmp/my project" --dest "/tmp/backups" --keep 3 --dry-run
